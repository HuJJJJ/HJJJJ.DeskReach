# 控制端最大化与画质切换修复

日期：2026-10-15。本轮接续 TurboJPEG 与差量更新，主程序为 HJJJJ.DeskReach.Windows。

## 为什么最大化后画面仍然很小

有两层布局问题：

1. MainFrom 的 closableTabControl1 只有默认的左、上锚定。主窗口变大时，标签页区域仍保持原尺寸；内部 MasterForm 即使 Dock=Fill，也只能填满这个固定区域。
2. MasterForm 将每张收到的图像按当时控件宽度另存成一个缩放位图，再用 AutoSize 显示。窗口尺寸变化时，没有新帧就不会重新缩放。差量更新会跳过静止桌面，因此这个问题更容易显现。只考虑宽度，还可能让画面高度超出可视区。

### 具体修改

[MainFrom.Designer.cs](</C:/Users/o/Desktop/新建文件夹/HJJJJ.DeskReach/HJJJJ.DeskReach.Windows/MainFrom.Designer.cs:62>)：将标签页锚定到四边，保留现有顶部连接控件和四周边距。

```csharp
closableTabControl1.Anchor = AnchorStyles.Top | AnchorStyles.Bottom
    | AnchorStyles.Left | AnchorStyles.Right;
```

[MasterForm.InitView](</C:/Users/o/Desktop/新建文件夹/HJJJJ.DeskReach/HJJJJ.DeskReach.Windows/MasterForm.cs:96>)：改用等比例适应可视区域的 Zoom。

```csharp
pictureBox.Dock = DockStyle.Fill;
pictureBox.SizeMode = PictureBoxSizeMode.Zoom;
```

[DisplayPendingScreenImage](</C:/Users/o/Desktop/新建文件夹/HJJJJ.DeskReach/HJJJJ.DeskReach.Windows/MasterForm.cs:477>)：直接持有接收端合成好的完整快照，删除提前缩放和额外位图分配。控件可以随窗口尺寸重新绘制同一张图片，静止桌面也能放大、缩小。旧图片仍在替换时释放，待处理图片仍只保留最新一张。

图像按宽、高共同限制保持比例，横竖比例不同时保留留白；完整桌面不会因窗口比例不同而被拉伸或截断。

## 为什么提高画质看起来没明显反应

本轮检查了真实菜单事件、屏幕数据包、发送端插件和 GetImage 参数，原有 JPEG 质量参数可以传递。限制出在发送端 ScaleFrame：每一档都固定使用原始宽、高的一半。比如 1920×1080 始终先变成 960×540，再进行 JPEG 编码；提高 JPEG 质量无法补回缩小时丢掉的文字细节。

[WindowsAPIScreenCapture.ScaleFrame](</C:/Users/o/Desktop/新建文件夹/HJJJJ.DeskReach/HJJJJ.DeskReach.Windows/WindowsAPIScreenCapture.cs:148>) 现在将画质与分辨率一同调整：

```csharp
int divisor = quality >= 80 ? 1 : 2;
int width = Math.Max(1, frame.Width / divisor);
int height = Math.Max(1, frame.Height / divisor);
```

| 菜单选项 | JPEG 质量 | 发送尺寸 | 用途 |
|---|---:|---|---|
| Speed | 1 | 原始宽、高各一半 | 优先减小传输量 |
| Low | 20 | 原始宽、高各一半 | 较低画质 |
| Nomal（现有菜单拼写） | 50 | 原始宽、高各一半 | 默认性能设置 |
| High | 80 | 原始分辨率 | 保留文字和图像细节 |
| Quality | 100 | 原始分辨率 | 更高 JPEG 质量 |

例如 2560×1440 屏幕，在 Nomal 下发送 1280×720，在 High / Quality 下发送 2560×1440。高清档的像素数变为默认档的四倍，编码、解码和传输开销也会增加。Quality 仍使用有损 JPEG 编码。

[ScreenPlugin 接收 ImageQuality 的分支](</C:/Users/o/Desktop/新建文件夹/HJJJJ.DeskReach/HJJJJ.DeskReach/Plugins/Screen/ScreenPlugin.cs:80>)：质量更新放在发送锁内，限制为 1～100，并请求下一帧完整刷新。静止桌面允许用缓存图像按新设置重新编码。

```csharp
lock (sendFrameLock)
{
    if (disposed) break;
    Quality = Math.Max(1, Math.Min(100, screen.ImageQuality));
    ViewContext.RequestKeyFrame();
}
```

仍保留在途 ACK 限制：当前更新确认后，下一次发送完整新画质画面。若当前确认超时，沿用原有两秒恢复机制。分辨率或质量发生变化时，差量编码器建立新的完整基准，接收端调整画布后再接收后续差量。

## 缩放后鼠标为什么也需要修改

Zoom 会使实际图像在控件内部居中，图像边缘可能与控件边缘不同。旧公式直接用鼠标坐标除以整个控件宽高，会把留白算进远程桌面，导致点击和画板偏移。

[GetDisplayedImageBounds / TryGetRemotePoint](</C:/Users/o/Desktop/新建文件夹/HJJJJ.DeskReach/HJJJJ.DeskReach.Windows/MasterForm.cs:264>) 按与 Zoom 相同的规则计算实际图像区域，先减去居中偏移，再转成现有协议的百分比坐标。点击、双击、滚轮、拖动、文件落点和画板都使用这套换算。

- 留白中的按下事件不发送给远程桌面。
- 按住拖动后移到留白中，移动和松开坐标限制在图像边界内，让远程鼠标可以正常释放。
- 仅观看模式不发送远程鼠标操作。

实际测量发现本机 PictureBox 默认 Zoom 绘制较慢，因此新增 [RemoteScreenPictureBox.OnPaint](</C:/Users/o/Desktop/新建文件夹/HJJJJ.DeskReach/HJJJJ.DeskReach.Windows/CustomControl/RemoteScreenPictureBox.cs:9>)，保留 Zoom 的布局规则，使用 SourceCopy、HighQualityBilinear、HighSpeed 绘制参数，绘制后还原 Graphics 状态。
